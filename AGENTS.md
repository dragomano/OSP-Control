# AGENTS.md

## Project

Tauri 2 + React 19 + TypeScript (no Tailwind, custom CSS) — desktop control panel for OSPanel 6, installed at `D:\OSPanel6` (CLI: `bin/osp.bat`).

## Commands

- `pnpm build` — tsc + vite (fast typecheck/build check)
- `pnpm test` / `pnpm test:watch` — Vitest (jsdom): unit tests for pure frontend logic, locale parity tests and `--k-*`, App smoke tests; tests live in `tests/` and are typechecked by `pnpm build` as well
- `pnpm coverage` — the same Vitest run with a v8 coverage report (`coverage/`, `src/**` only) and minimum thresholds; CI runs it instead of `pnpm test`
- `pnpm tauri:build` — portable build: `tauri build` produces only the exe (bundling is disabled in `tauri.conf.json` — no MSI/NSIS installers are created), then `scripts/make-portable.mjs` assembles `dist-portable/OSP_Control_<version>_<arch>/` — the exe with a proper `locales/` folder next to it; CI packs the folder into a zip for the release
- `cargo check` — run in `src-tauri` (Rust lives in `~/.cargo/bin`: `export PATH="$USERPROFILE/.cargo/bin:$PATH"`)
- `pnpm lint` / `pnpm format` — Biome

## Mandatory verification after changes

After every change to project files, run the commands one by one in this order and fix all reported errors until the result is clean:
1. `pnpm lint`
2. `pnpm fix`
3. `pnpm format`
4. `pnpm build`
5. `pnpm test`

Consider the task complete only when all commands pass without errors. For changes in `src-tauri` also run `cargo test` there.

## Structure

- `src/App.tsx` — root component: state, orchestration, dialogs and toasts
- `src/components/shared.ts` — shared types, helpers and hooks (Page, Notify, formatSize, useDismiss, etc.)
- `src/components/pages/` — pages (Overview, Services, Projects, Settings)
- `src/components/widgets/` — reusable widgets (RowMenu, StatusDot, PageHeader, Metric, ServiceCard, ActivityRow, FilterFacet)
- `src/components/dialogs/` — dialogs and search palette (QuickSearch, ModuleSelect, ProjectModulesDialog, CreateProjectDialog)
- `src/components/tables/` — table pages (Configs, Logs, Backups)
- `src/ospanel.ts` — typed invoke-command adapter
- `src/i18n.ts` — t() context, dictionary loading, hot-reload on focus
- `src/theme.ts` — accent themes (hue rotation), fonts, scale
- `src-tauri/src/main.rs` — all commands; `src-tauri/resources/locales/*.json` — dictionaries

## Conventions (do not violate)

- No hardcoded UI strings: only `t('key')` plus keys in both dictionaries. Adapter errors are codes (`err.*`); Rust commands return errors as `CommandError { code, params }`, and the frontend translates them via `errorText(t, error, fallbackKey)` from `i18n.ts`.
- Accent colors go through CSS variables `--k-*` (generated by `theme.ts`); never hardcode hex values.
- Rust commands: argument whitelist, `fs::canonicalize` + `starts_with` for paths, never execute user input directly.
- Create an automatic backup before restoring configurations (already implemented).
- The user edits `locales` files by hand — never overwrite them at runtime.
- Code comments (TS/TSX, CSS, Rust, configs) — English only. Russian is allowed only in `locales` dictionaries and in data reproducing panel output (test fixtures, log regex parsers).

## Known specifics

- dev copy of the locales: `src-tauri/target/debug/locales/` (created by Tauri automatically)
- Module and project state comes from the panel's HTTP API: `GET /getmodules` and `/getprojects` (address from `system/program.dat` → `general.api_ip`/`api_port`, factory default `127.0.1.0:80`; the panel must be running). Do not parse the text tables of `osp.bat` — they are localized and break when the panel interface language changes.
- The panel's JSON is not strictly valid: raw control bytes appear inside strings (NULs from env blocks) — parse it only via `parse_osp_json()` in `main.rs`.
- Machine-readable sources: JSON API (modules/projects), `config/<module>/module.ini` (`enabled = 1`), `bin/osp.bat` (`OSP_VERSION=`).
