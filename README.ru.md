# OSP Control

![Stack](https://skillicons.dev/icons?i=tauri,rust,react,ts,vite)

**Русский** · [English](README.md)

UI-надстройка для OSPanel 6. Управление локальным окружением: сервисы, проекты, домены, конфигурации, журналы, резервные копии — в одном окне, с темами и мультиязычным интерфейсом.

> Неофициальный инструмент, создан в исследовательских целях, не связан с OSPanel / OpenServerPanel. Название «OSPanel» — товарный знак правообладателя.

## Возможности

### Обзор

- Приветствие по времени суток и имени пользователя Windows.
- Метрики окружения: активные сервисы, количество проектов, использование RAM рабочими процессами модулей, открытые порты и конфликты.
- Быстрый обзор состояния модулей и лента последней активности из журналов панели.
- Кнопка синхронизации с панелью.

### Модули

- Список модулей локального окружения с группировкой: веб-серверы, языки и среды выполнения, базы данных, кэш и очереди, DNS, почта, инструменты и прочее.
- Старт / стоп / перезапуск отдельного модуля и перезапуск всех запущенных сразу.
- Фильтр по группам, копирование имени сервиса, индикаторы состояния (работает / остановлен / требует внимания).
- Данные берутся из HTTP API панели (`/getmodules`), а не из локализованных текстовых таблиц.
- Ручное обновление PHP (в пределах ветки), Apache 2.4, Nginx (в пределах ветки) и Caddy 2, с возможностью проверки обновлений при запуске приложения.
- Проверка SHA-256 архивов и версий бинарников, сохранение настроек, полная резервная копия модуля, откат и восстановление прерванной операции. Остановленные веб-серверы остаются остановленными.
- Если версия архива Caddy указана неверно, допускается проверенная более новая стабильная патч-версия той же ветки; сохраняется и отображается фактическая версия бинарника.
- Источники обновлений настраиваются отдельно для каждого семейства модулей (PHP, Apache, Nginx, Caddy): GitHub Releases или HTTPS-каталоги Windows ZIP-сборок с SHA-256. Проверяются сверху вниз, до 32 адресов на семейство; пустой список отключает проверку для него.
- Учитываются ревизии пакетов PHP (например, `8.5.12-2`): пересобранный пакет той же версии тоже предлагается и отображается корректно.

### Проекты

- Список проектов с поиском по доменам, путям и меткам (`#метка` находит точное совпадение) и фильтрами по SSL/TLS, версии PHP, HTTP-движку и меткам («любая» / «все» / «без меток»).
- Цветные метки (до 12 на проект, до 32 символов) со своим цветом для каждой метки, массовое добавление и удаление у выбранных проектов.
- Сортировка по времени изменения, домену или названию меток; в строке видны дата и время последнего изменения с группами «Сегодня / Вчера / Ранее» и файл, изменённый последним.
- Создание проекта (домен, HTTP-движок, версия PHP, Node), переименование домена и удаление проекта. При переименовании переносится папка `home/<домен>` и домен в `project.ini`, метки и настройки модулей сохраняются, а `project.ini` предварительно копируется.
- Включение и отключение SSL/TLS-сертификата для проекта.
- Открытие в браузере, открытие папки проекта, копирование домена и пути.
- Открытие проекта во внешнем редакторе (автоопределение установленных редакторов).
- Настройка модулей проекта (HTTP/PHP/Node, авто или глобальные значения) с правкой файла настроек.
- Страница настроек проекта с вкладками сверху: обзор, домены, окружение, веб-сервер, конфигурации, меню и задания. Открывается по названию проекта или через «Настройки проекта» в меню строки; поиск, фильтры и метки списка сохраняются при возврате.
- Несколько доменов в общей папке проекта, псевдонимы, основной домен, категория, каталоги, порты, TLS и backend-прокси. Переменные среды редактируются в `.osp/env.ini`.
- Визуальный редактор меню проекта на вкладке «Меню»: дерево, категории, перетаскивание, свойства пунктов, выбор иконок и отмена / повтор — как в редакторе меню OSPanel. Общая кнопка «Сохранить» записывает `.osp/menu.ini`, сохраняя комментарии, неизвестные поля и резервную копию; глобальное меню не затрагивается. Черновик сохраняется при переходе между вкладками проекта.
- Визуальный редактор заданий на вкладке «Задания»: создание, дублирование, удаление, переименование, включение, готовые расписания или пять полей cron, лимит запусков и команда. Дни недели — от 1 (понедельник) до 7 (воскресенье). Черновики сохраняются между вкладками и доменами, включая незавершённый ввод. Общая кнопка «Сохранить» (или Ctrl+S на вкладке заданий) проверяет поля и записывает `.osp/tasks.ini` с резервной копией и защитой от внешних правок, сохраняя комментарии, другие домены, BOM и переводы строк. Применение — после перезапуска OSPanel.
- Диагностика выбранного сохранённого домена: файл настроек и состояние проекта в OSPanel, необходимые модули, неприменённые настройки, каталоги проекта и сайта, DNS, TCP-соединения с HTTP/HTTPS/backend, наличие файлов TLS, доступность локального дополнения конфигурации, определения меню и заданий, последние 64 КиБ журнала ошибок домена. Результаты разделены на успешные, замечания, проблемы и непроверенные; есть пояснения, подсказки, переходы к настройкам и фильтр проблем. Несохранённые изменения и устаревшие результаты отмечаются. Проверки не запускают скрипты и страницы проекта, не меняют файлы и не перезапускают OSPanel автоматически; ответы HTTP, доверие сертификатам и полный синтаксис веб-сервера не проверяются.
- Редактор конфигураций домена с отдельной подсветкой Nginx, Apache и Caddyfile; также доступно прямое редактирование `project.ini`. Перед заменой каждого существующего файла создаётся точная копия в `backups/project-settings`; внешние изменения обнаруживаются до записи. После сохранения предлагается перезапуск OSPanel.
- Автозапуск модулей на основе проектов и перезапуск панели из UI.

### Конфигурации

- Просмотр конфигов модулей с подсветкой синтаксиса (highlight.js).
- Поиск, фильтр по модулю, открытие файла и папки, копирование содержимого.
- Создание резервной копии конфигураций перед изменениями.

### Редактор меню

- Визуальный редактор меню OSPanel (`system/menu.dat`): дерево пунктов и категорий (один уровень вложенности), перетаскивание и перемещение пунктов вверх / вниз.
- Свойства пункта: подпись, команда, рабочий каталог, выбор иконки Font Awesome, видимость, скрытие окна запускаемой программы, разделители, условия запуска (алиас домена, запущенный модуль, стартовая команда, Windows Terminal, оболочка, веб-интерфейс) и обязательная категория модуля. Неизвестные поля сохраняются и доступны для правки.
- Добавление, дублирование и удаление пунктов; добавление, переименование и удаление пустых категорий; отмена / повтор, поиск, свернуть / развернуть всё — состояние дерева запоминается.
- Сохранение проверяет меню, создаёт автоматическую резервную копию и замечает изменения `menu.dat` вне редактора; в уведомлении предлагается перезапуск OSPanel. Копии меню восстанавливаются из раздела «Резервные копии».

### Журналы

- Просмотр логов панели и доменов с автообновлением.
- Вкладки «Все / ошибки / предупреждения» со счётчиками, поиск по содержимому, копирование строк.
- Очистка текущего журнала или всех сразу с подтверждением; файлы остаются на месте для новых записей.

### Резервные копии

- Копии конфигураций, дампы баз данных (MySQL, MariaDB, PostgreSQL), zip-архивы проектов (без node_modules и vendor) и точные копии `system/menu.dat`.
- Создание, восстановление и удаление копий; перед восстановлением текущее состояние сохраняется автоматически (для меню дополнительно предлагается перезапуск панели).
- Фильтр по типу: конфигурации, базы данных, проекты, меню OSPanel.
- Открытие папки с резервными копиями.

### Настройки

- Путь к установке OSPanel с выбором папки.
- Автозапуск приложения вместе с Windows и автозапуск модулей из проектов.
- Сворачивание в системный трей при закрытии, уведомления.
- Тема (тёмная / светлая / системная), шесть акцентных цветов, шрифт и масштаб интерфейса от 80 до 130%.
- Выбор языка, перечитывание переводов на лету.
- Проверка обновлений модулей при запуске и настройка источников обновлений для каждого семейства модулей: один HTTPS-адрес в строке, до 32, с проверкой формата; пустой список отключает проверку.

### Общее

- Быстрый поиск по разделам и опциям по клавише `/`, стрелкам и Enter (командная палитра).
- Иконка в системном трее (показать окно / выход).
- Один экземпляр: повторный запуск выводит на передний план уже открытое окно.
- Окно открывается по размеру рабочей области экрана, ручной размер окна запоминается между запусками.
- Карточка обратной связи в боковой панели со ссылкой на GitHub Discussions.
- Локализация: русский, английский, украинский, белорусский, испанский — [подробнее](#локализация).

## Разработка

```bash
pnpm install
pnpm tauri:dev        # приложение с живой перезагрузкой UI
pnpm build            # только фронтенд (tsc + vite)
pnpm coverage         # тесты с отчётом покрытия и порогами
pnpm tauri:build      # портативная сборка в dist-portable/ (exe + locales/)
pnpm lint             # Biome: линт + проверка форматирования
pnpm format           # Biome: форматирование
pnpm test             # Vitest (jsdom)
```

`pnpm tauri:build` собирает только портативную версию — установщики (MSI/NSIS) не создаются. Результат — папка `dist-portable/OSP_Control_<версия>_<арх>/`: `osp-control.exe` и правимая папка `locales/` рядом с ним. Приложению нужен WebView2 Runtime — как и любому Tauri-приложению на Windows; если его в системе нет, поставьте Evergreen WebView2 Runtime от Microsoft.

## Переносимые настройки

Настройки интерфейса, размер окна, метки проектов и их цвета, источники обновлений модулей и свёрнутые категории меню хранятся в `settings.toml` рядом с exe, независимо от рабочей директории. В свежей переносимой сборке файла нет: до первого изменения настройки или сохранения метаданных используются встроенные значения. Папка приложения должна быть доступна для записи; автоматического переноса настроек в AppData при ошибке записи нет.

При первом запуске после обновления старые настройки из localStorage WebView и `settings.json` в AppData переносятся автоматически. Существующий TOML имеет приоритет. До успешной записи исходные данные сохраняются; затем старый JSON переименовывается в `settings.json.migrated`, а перенесённые ключи localStorage удаляются.

Для редактирования используется `toml_edit`: комментарии, оформление остальных значений и неизвестные ключи сохраняются. Записи выполняются последовательно через временный файл с атомарной заменой; предыдущая версия остаётся в `settings.toml.bak`. Повреждённый TOML или неподдерживаемая версия схемы отображаются как ошибка и автоматически не перезаписываются. Исправьте файл или восстановите резервную копию и повторите попытку. Ручные изменения загружаются при следующем запуске приложения. Оформление изменяемого значения может обновиться.

Пример структуры приведён в [английской версии README](README.md#portable-settings). Отсутствующие поля используют встроенные значения.

Автозапуск Windows по-прежнему использует системный реестр, а технический профиль и кеш WebView2 остаются в AppData. Настройки приложения там больше не сохраняются. В браузерном режиме используется localStorage. При сборке переносимой версии настройки разработки в папку релиза не копируются.

## Обновление приложения

Для ручной проверки используйте кнопку-иконку справа от надписи **OSP Control** в шапке левой панели, оформленную как расположенная ниже кнопка **«Открыть папку OSPanel»**. Кнопка проверки обновлений остаётся доступной и при свёрнутой левой боковой панели. Нажмите её, чтобы открыть окно обновления приложения. В разделе **Настройки → Автозапуск и уведомления** остаётся только отдельный переключатель **«Проверять обновления приложения при запуске»** (по умолчанию выключен).

Новая версия показывается компактным уведомлением, из которого открывается диалог с описанием релиза и кнопкой **«Обновить и перезапустить»**. Описание выводится из Markdown в безопасные элементы: сырой HTML показывается как обычный текст. Установка всегда требует подтверждения; автоматической установки нет.

Источник — последний стабильный GitHub Release в `dragomano/OSP-Control`, архив `OSP_Control_<версия>_<арх>.zip`. Проверяются точный адрес, размер, SHA-256 из GitHub, структура ZIP и архитектура PE. SHA-256 защищает от повреждения загрузки, но не заменяет независимую подпись издателя.

Дополнительного постоянного updater нет: на время операции рядом с exe создаётся `.osp-control-update` с копией того же exe и архивом. Нужны права записи и свободное место для архива, распаковки и резервной копии. Служебный процесс ждёт завершения приложения и **до замены файлов** сохраняет и проверяет копию прежнего exe и всей папки `locales/` в `.osp-control-backups/<идентификатор>/` рядом с приложением. Если создать или проверить копию не удалось, установленные файлы не заменяются.

Затем **исполняемый файл и вся папка `locales/` заменяются версиями из релиза**, без слияния: ручные правки и дополнительные языки остаются только в резервной копии. Пользовательские настройки не затрагиваются. При ошибке замены или если новый интерфейс не подтвердил запуск за 60 секунд, восстанавливаются прежний exe и прежняя папка `locales/` вместе (если её не было — восстанавливается отсутствие папки). После подтверждённого запуска либо успешного отката временная `.osp-control-update` удаляется, но `.osp-control-backups/` сохраняется. Каждый бэкап получает отдельную папку; старые копии автоматически не удаляются. Их можно удалить вручную после проверки приложения и переноса нужных переводов.

После аварийного отключения питания автоматический откат не гарантируется. Закройте все процессы приложения и перед удалением `.osp-control-update` восстановите **оба компонента из одной завершённой копии** в `.osp-control-backups/<идентификатор>/` (завершённая копия содержит файл `complete`): скопируйте `osp-control.exe` под прежним именем exe в каталог приложения, а текущую `locales/` полностью замените папкой `locales/` из той же копии. Не копируйте словари поверх существующих: так останутся лишние файлы. Маркер `no-locales` означает, что до обновления папки переводов не было — при восстановлении её нужно убрать. Путь к копии текущей операции записан в `.osp-control-update/backup-path.txt`. `previous.exe` и `previous-locales/` внутри временной папки — перемещённые оригиналы для автоматического отката, не отдельные программы. Не удаляйте временную папку до восстановления. В режиме разработки установка намеренно запрещена.

## Локализация

Интерфейс доступен на пяти языках. Список совпадает с выбором языка в **Настройках → Внешний вид**, где языки отсортированы по названию на самом языке.

| Язык                               | Код  | Формы множественного числа    | Словарь                                          |
| ---------------------------------- | ---- | ----------------------------- | ------------------------------------------------ |
| **English** (английский) — базовый | `en` | `one`, `other`                | [`en.json`](src-tauri/resources/locales/en.json) |
| Español (испанский)                | `es` | `one`, `many`, `other`        | [`es.json`](src-tauri/resources/locales/es.json) |
| Беларуская (белорусский)           | `be` | `one`, `few`, `many`, `other` | [`be.json`](src-tauri/resources/locales/be.json) |
| Русский                            | `ru` | `one`, `few`, `many`, `other` | [`ru.json`](src-tauri/resources/locales/ru.json) |
| Українська (украинский)            | `uk` | `one`, `few`, `many`, `other` | [`uk.json`](src-tauri/resources/locales/uk.json) |

Английский — базовый язык: всё, чего нет в другом словаре, молча показывается по-английски.

Переводы лежат в `src-tauri/resources/locales/*.json` и встраиваются в бинарник. В портативной сборке копия — в `locales/` рядом с exe: правьте файлы там, изменения подхватываются при возврате фокуса в окно или кнопкой «Перечитать переводы» в настройках.

Новый язык — это один файл `<код>.json` (например `de.json` или `pt_BR.json`) в `locales/` рядом с exe; в dev-сборке — `src-tauri/target/debug/locales/`. Код — 2–8 символов: латиница, цифры, `-` и `_`. Язык появится в настройках сам, пересборка не нужна. Формат файла:
- JSON-объект «ключ — непустая строка»; семейство форм множественного числа — вложенный объект (см. ниже);
- ключи перечислены в том же порядке, что в `en.json` (базовый язык), поэтому два словаря можно сравнивать построчно;
- `lang.name` — название языка на нём самом («Deutsch»); без него язык не появится в списке настроек;
- `lang.code` — код, совпадающий с именем файла; других ключей `lang.*` быть не должно;
- полный набор ключей из `en.json`: недостающие ключи молча показываются по-английски, лишние — не переводятся никогда;
- плейсхолдеры `{var}` — те же имена, что в `en.json`;
- формы множественного числа — вложенный объект под ключом семейства, например `"settings.sourcesCount": { "one": "{count} address", "other": "{count} addresses" }`. Формы — CLDR-категории самого языка (`Intl.PluralRules`): английскому и немецкому достаточно `one`/`other`, русскому нужны все четыре, арабскому добавились бы `zero`/`two`. Добавлять нужно только те формы, которые языку нужны. Старый плоский стиль (`"settings.sourcesCount.one"`) тоже читается — файл, записанный так, продолжает работать. В русском, украинском и белорусском `other` покрывает дробные числа, и существительное в нём стоит в родительном единственном («1,5 файла»).

При загрузке файла приложение проверяет его и перечисляет найденные проблемы в тосте; в репозитории те же правила проверяют parity-тесты (`pnpm test`). Чтобы встроить язык в дистрибутив, добавьте тот же файл в `src-tauri/resources/locales/`, импорт в `src/i18n.ts` и fallback в `src-tauri/src/locales.rs` — тесты подхватят новый словарь автоматически.

## Безопасность

Все команды Rust валидируют вход: белый список действий, канонизация путей с проверкой принадлежности каталогу OSPanel, резервные копии перед восстановлением конфигураций. Ничего из пользовательского ввода не исполняется напрямую.
